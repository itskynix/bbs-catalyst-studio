BOLUM 0 - COKME RISKI TRIAJI (bu siraya gore uygulanacak)
--------------------------------------------------------------------------------
Asagidaki 6 madde, dogrudan crash / OutOfMemoryError / sunucu coku / veri
kaybi ile sonuclanabilecek maddeler oldugu icin FAZ 0 olarak once ele alinir.
Digerleri (animasyon, locale, hijyen) davranis bozuklugu/UX sorunu olup
oyunu cokertmez; onlar FAZ 1-3'te gelir.

 [P0-1] DEFECT-18 - PacketCrusher.receive() (network/PacketCrusher.java)
   Risk: `new byte[size]` ve `new ByteArrayOutputStream(total * BUFFER_SIZE)`
   client/sunucudan gelen ham int degerlerine hicbir ust sinir konmadan
   allocate ediyor. Bozuk/kotu niyetli buyuk size/total -> OutOfMemoryError
   -> istemci VEYA sunucu coker (dedicated server'da TUM oyunculari etkiler).
   `total * BUFFER_SIZE` int tasmasi (overflow) negatif kapasiteye de yol
   acabilir -> IllegalArgumentException -> paket isleme thread'inde
   yakalanmamis istisna.
   Yontem: MAX_PACKET_SIZE (orn. 32 MB) ve MAX_CHUNKS sabiti tanimla;
   size/total bu siniri asarsa veya negatifse paketi SESSIZCE (loglayarak)
   reddet, allocate ETME. Bu degisiklik protokolu bozmaz (ayni id/index/
   total/size alan sirasi korunur), sadece savunma katmani eklenir.

 [P0-2] DEFECT-19 - ServerNetwork.crusher static/paylasimli
   Risk: Tek `crusher` instance'i TUM oyunculara ortak; art arda/eszamanli
   buyuk transferlerde chunk'lar (Map<Integer, ...>) karisabilir VE
   yarim kalan transferler asla temizlenmez -> uzun vadede bellek sizintisi
   -> uzun sureli acik sunucularda OOM crash.
   Yontem: Map<UUID, ServerPacketCrusher> ile oyuncu-basina crusher; mevcut
   BBSMod.registerEvents() icindeki ServerPlayConnectionEvents.DISCONNECT
   noktasina crusher temizligi eklenecek (zaten `actions.stopFor(player)`
   burada cagriliyor, ayni yere ekleme yapilacak - yeni bir event kaydina
   GEREK YOK).

 [P0-3] DEFECT-20 - ServerNetwork: NaN/Infinity ve izinsiz paket kabulu
   Risk (crash): handleTeleportPlayer x/y/z/yaw/pitch degerlerini dogrudan
   player.requestTeleport(...)'a veriyor; NaN/Infinity gelirse (bozuk paket
   veya kotu niyetli client) sunucu tarafi konum/chunk hesaplamalarinda
   (chunk index NaN->int cast) coken oyuncu/entity tracking hatasi veya
   istemci tarafinda render NaN yayilimi olusabilir.
   Risk (guvenlik/izin): handleSharedFormPacket, handlePauseFilmPacket,
   handleAnimationStateTriggerPacket icinde PermissionUtils.arePanelsAllowed
   kontrolu YOK -> yetkisiz oyuncu bu paketleri gonderip diger oyunculara
   relay/etki yaratabilir (dogrudan crash degil ama istismar edilebilir).
   Yontem:
     - handleTeleportPlayer basinda Double.isFinite(x/y/z) &&
       Float.isFinite(yaw/bodyYaw/pitch) kontrolu; degilse paketi at.
     - Eksik 3 handler'a arePanelsAllowed kontrolu eklenecek (diger
       handler'larla ayni desen: server, player parametreleri zaten mevcut).
     - handleCutStructure/handleSaveStructure: from/to arasi hacim
       (|dx|*|dy|*|dz|) icin MAX_STRUCTURE_VOLUME sabiti ile ust sinir;
       asarsa StructureSaver.save/clear cagrilmadan reddedilecek (dev
       hacimli kayit = uzun senkron NBT yazimi = sunucu tick donmasi riski).

 [P0-4] DEFECT-17 - FolderManager.getFile() path traversal
   Risk: name icinde ".." gecen bir kimlik (ornegin CLIENT_MANAGER_DATA
   akisindan gelen film id'si) folder disina cikip rastgele dosya
   okuma/YAZMA/silme yapabilir. Kritik bir yapilandirma dosyasinin
   uzerine yazilmasi/dosyanin silinmesi bir sonraki baslatmada
   FabricLoader/BBSMod init asamasinda coken bir sunucu/istemciyle

   Yontem: StructureSaver.java'da zaten kanitlanmis desen aynen

       File f = new File(getFolder(), name + ext);
       if (!f.toPath().normalize().startsWith(getFolder().toPath().normalize()))

   Cagiran taraflarin null donusunu tolere ettigi (BaseManager.load/save)
   ayri ayri dogrulanacak; tolere etmiyorsa o cagri noktasina da null
   kontrolu eklenecek.

 [P0-5] DEFECT-02 - CatalystProject.load() bozuk dosyada null + sessiz

BAGIMSIZDIR: PacketCrusher sadece kac chunk / chunk ne kadar buyuk seviyesini
